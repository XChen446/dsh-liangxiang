# 日终并发验证

2026-10-19；源码基线 `9b24315`，1.2.0-rc.8。新增的是回归测试，不修改投票、限流或排期规则。

## 场景与结果

使用实际 Backend HTTP 处理器、Ed25519 签名与独立安装身份、真实文件 SQLite/WAL。
测试准备阶段登记合成身份并填充余额，不消耗社区入梁券；业务请求不走 unsigned 模式。
所有服务仅监听本机随机端口，不访问社区服务器或用户 Profile。

| 场景 | 验证结果 |
| --- | --- |
| 1000 户同屏障释放，各投 20 炷 | 1000 条 TCP 连接，1000 个 HTTP 200；合计 20,000 炷，1000 位香客，每户余额 20→0 |
| 原样重放这 1000 笔 | 全部 HTTP 200、`replayed=true`、本次 `spent_incense=0`；仍只有 1000 笔接受记录与 1000 张票据，无重复扣香 |
| 100 户，各自手动/自动争 20 炷，双方同时重复 | 共 400 个请求，仅 200 个独立意图；每户最终用香 20、余额 0，总香火 2000、香客 100，不依赖请求到达顺序 |
| 64 户，各请求 500 炷，沿用默认每户预算 | 首笔各接受 50 炷；新意图 429，同 ID 重放仍 200，改 payload 冲突 409；每户剩余 950 |
| 128 户的旧案请求在午夜后到达 | 全部 409；重放保持拒绝，昨日余额未扣，今日余额不继承，今日总香火/香客为 0 |
| 32 个真实 Host 日终服务同时启动 | `DayEndService → BackendLiangService → BackendClient → 签名 HTTP → SQLite` 完整链路，32 笔普通意图接受，共 640 炷、32 香客 |

每个场景均检查 SQLite `quick_check=ok`、WAL、外键及余额不为负/不超支。
接受记录、持久化票据、逐户账本、全局香火与唯一香客相互核对；无 500、锁库或未处理请求错误。
手动与自动的竞争在服务端共享同一账本；没有为自动倾炉增加预算或特权。

## 本机一次实测

环境：Apple M4、arm64、24 GiB 内存，Node 22.23.1；单进程 Node Backend 与本地磁盘。
以下为完整五场景专项通过时记录的一个样本，无速度通过线：

| 批次 | 全部完成 | 请求/秒 | p50 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1000 户首次倾炉 | 1167 ms | 857 | 251.3 ms | 1113.5 ms | 1134.3 ms |
| 1000 笔相同意图重放 | 285 ms | 3503 | 269.8 ms | 272.4 ms | 272.6 ms |

延迟从客户端 HTTP 发起计至响应体读取完毕，包含签名校验、建连、事务和响应；身份登记、
准备签名不计入突发用时。1000 户先全部就绪再同时释放，业务时钟固定为 23:59:00；
实际处理仍使用真实经过时间，**并非宣称 1000 户必须在真实一秒内全部完成**。

## 可复跑入口与边界

```sh
node node_modules/vitest/vitest.mjs run tests/backend-day-end-concurrency.spec.ts --reporter=verbose
```

专项共 5 项，耗时约数秒；测量值写入测试输出。只断言结果一致性，不断言硬件相关的吞吐或延迟。
本轮全量类型、lint、658 项单元/集成测试、构建和包体预算通过。
需要支持约 2000 个本地 TCP socket 的文件描述符额度；资源不足是测试环境限制。
Host 的提前 5 秒截止、取消长按、手动结束后 2 秒等待及窗口内/跨日恢复另见 `tests/day-end.spec.ts`。

这不是公网、TLS、跨地域网络、生产磁盘或生产峰值容量验收，也没有模拟多个 Backend 进程
同时写同一库。当前部署契约仍为单 Backend 进程；进程内按安装限流不能推导为多进程全局限流。
本轮 1000 户未触及默认 4096 个活跃限流身份容量，不能据此保证任意规模不返回保护性的 429。
受限环境、恶意流量、长时间断网、崩溃/磁盘满恢复及线上容量仍需在相应环境单独验证。
