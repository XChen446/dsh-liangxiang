# 安装后的欢迎与更新引导

适用版本：**1.2.0**。正式发布、主线集成与生产部署分别核验；本文不代表 npm 或运行环境已升级。

## 现行行为

- 首次欢迎保留在线、离线两个明确选择。等待或刷新不会代替用户点击，也不会自动提交模式选择。
- 明确选择成功后，Host 持久化模式偏好，浏览器记录欢迎已完成，并进入当前版本的更新说明。
- 同一浏览器、同一来源已打开的标签页同步欢迎和当前版本说明的完成状态，不要求重复选模式。
  清空存储不会触发模式操作；不同浏览器的引导记录各自独立。
- 更新说明从顶部显示，支持滚动、键盘确认和 Escape；案牍的当前版本入口随时可重看。
- 说明保留 QQ 二维码、三位公开贡献者鸣谢和 23:59 日终上香介绍。日终开关默认关闭，说明只在悬停或聚焦时展开。
- 引导不投票、不启用日终上香，也不改变既有香火账本。

## 回归范围

`tests/browser/post-install-guidance.spec.ts` 直接运行于真实 tarball 安装的 DSH：

- 推进浏览器时钟两分钟并刷新，欢迎仍等待明确选择，无模式、投票或日终设置请求。
- 分别通过在线、离线按钮完成首次选择，刷新和新标签页不重复遮挡；Host 状态与选择一致。
- 已打开的两个首次欢迎标签页只需完成一次模式选择、一次版本确认。
- 更新说明可从案牍重新打开，初始位置在顶部，并可用 Escape 关闭。
- 首次说明中的日终时刻、右键方向提示、二维码和鸣谢实际可见；日终按钮显示已关闭。

同时运行既有 `welcome.spec.ts`、`release-notes.spec.ts`，保留二维码原图加载、边界、三位完整鸣谢、滚动和 Axe 检查。

在线选择场景要求 `LIANGXIANG_SMOKE_BACKEND_URL` 显式指向回环测试服务，否则跳过；
测试结束恢复离线模式与日终关闭。专项结果及完整验证边界见
[`RELEASE_READINESS_1_2.md`](RELEASE_READINESS_1_2.md#安装与浏览器)。

本次验证只使用独立临时 Profile、SQLite 和本机服务；未修改用户 Profile、真实社区数据或其他手测环境。
